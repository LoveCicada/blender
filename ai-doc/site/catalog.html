数据布局 makesdna

定义写进 .blend 的 C 结构：Mesh、Object、Scene、Material 等。这是「磁盘上的真相」，不是编辑器算法。

路径
source/blender/makesdna/，例如 DNA_mesh_types.h
上游
无（最底层布局）。构建时由 DNA 工具生成访问代码。
下游
blenkernel、blenloader、makesrna

模块数据布局物体 / 网格 / 材质

深讲：DNA。不展开每个版本修补。

属性反射 makesrna

把 DNA 字段和运行时函数暴露成属性、枚举、函数。面板、Python bpy、Operator 属性都经过 RNA，而不是直接扫结构体。

路径
source/blender/makesrna/
上游
makesdna、blenkernel
下游
Python UI、windowmanager（Operator 属性）

模块属性反射UI / Python

深讲：RNA。

运行时对象 blenkernel

ID 数据块的创建、拷贝、释放、命名、用户计数，以及 Mesh/Object/Scene 的核心逻辑（BKE_*）。编辑器和修改器改数据，最后多半落到这里。

路径
source/blender/blenkernel/，例如 BKE_mesh.hh
上游
makesdna、Operator、bmesh（写回时）
下游
depsgraph、blenloader、modifiers

模块运行时对象物体 / 网格 / 修改器

深讲：MeshRuntime / BMesh。

文件读写 blenloader

把 DNA 结构读写为 .blend。分析建模/渲染时只要知道：打开文件 = 重建 ID 图，不是「加载一棵游戏场景树」。

路径
source/blender/blenloader/、blenloader_core/
上游
makesdna
下游
blenkernel（得到 Main 数据库）

编辑态拓扑 bmesh

编辑模式使用的半边式网格：顶点/边/环/面互相指。适合挤出、切割、溶解。退出编辑或求值需要时，再转成 Mesh 的连续数组。

路径
source/blender/bmesh/
上游
editors/mesh、transform
下游
Mesh / BKE → depsgraph

模块拓扑编辑编辑模式

深讲：BMesh · 挤出 / BMO。

几何与属性 geometry

几何节点和通用属性（域、类型、字段）的求值底座。修改器和节点把「网格当数据」处理时走这里，而不是 BMesh 的编辑算子。

路径
source/blender/geometry/
上游
blenkernel、几何节点（本轮弱写）
下游
modifiers、depsgraph

模块运行时对象修改器

后续：C 里若碰到几何节点修改器再展开。不写节点语言全集。

修改器 modifiers

非破坏叠加：细分、镜像、实体化、几何节点修改器等。参数存在 DNA 里；真正变形多在 Depsgraph 求值对象时发生，视口和渲染看到的是求值后的网格。

路径
source/blender/modifiers/；面板在 scripts/startup/bl_ui/properties_data_modifier.py
上游
Object / Mesh、editors/object
下游

根据「谁依赖谁」求出给绘制/渲染看的世界：应用修改器、约束、实例、动画。原数据尽量不动；求值结果是副本或缓存。

下游

路径追踪 intern/cycles

独立渲染器：同步 Blender 场景、构建 BVH、integrator、device kernel。F12 出图的主路径。与视口 Draw 分道，只共享求值后的场景语义。

路径
intern/cycles/（blender/ 同步、scene/、integrator/、kernel/、device/）
上游
render、depsgraph、shader nodes
下游
CPU / GPU device（预编译库，分析不拉）

模块离线渲染F12 / 材质

深讲：Cycles sync / kernel。

着色节点 nodes/shader

材质节点树的定义与执行接口。同一套节点语义供给 EEVEE（编 GPU shader）和 Cycles（编 SVM/OSL/kernel 闭包）。

路径
source/blender/nodes/shader/；编辑器空间 editors/space_node/
上游
NodeTree DNA、节点菜单
下游
EEVEE、Cycles
