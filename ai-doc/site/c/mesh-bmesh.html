blenkernel / bmesh

为什么编辑不用数组网格

持久 Mesh 是按域打包的数组 + 属性，适合求值、绘制、存盘。挤出、溶解需要「这个面的邻边」——那是半边 BMesh。

建模入口 Mesh / BMesh 进出编辑模式 挤出与 BMO 修改器

它解决什么

同一份网格要同时满足存盘、求值、绘制，以及「这个面的邻边」。前三件事喜欢按域打包的数组；最后一件需要半边。两套表示并存，而不是把 DNA 改成指针网，也不是让挤出走线性扫描。

持久 Mesh

DNA 字段见数据 · DNA。Mesh::runtime（BKE_mesh_types.hh 的 MeshRuntime）不进文件。编辑态指针是：

/* MeshRuntime */
std::shared_ptr<BMEditMesh> edit_mesh;
/* plus mesh_eval, wrapper_type, batch_cache, ... */

BMEditMesh（BKE_editmesh.hh）：BMesh *bm、looptris、selectmode、needs_flush_to_id。访问：BKE_editmesh_from_object（blenkernel/intern/editmesh.cc）。

BMesh 元素

source/blender/bmesh/bmesh_class.hh：每个元素带 BMHeader.hflag。

  • BMVert：坐标、盘状边 e
  • BMEdge：两端点、径向环
  • BMLoop：面角，绕面 next/prev，绕边 radial_*
  • BMFace：l_first、材质号

选择位 BM_ELEM_SELECT（hflag 第 0 位）。测试：BM_elem_flag_test；写入：BM_elem_select_set。网格上还有 totvertsel 等计数。

和邻居的边界

层它写什么它不写什么
DNA Mesh数组顶点数、属性层、进文件的字段半边邻接、编辑选择历史
BMesh点/边/环/面互相指，hflag 选择不进 .blend
BMEditMesh挂在 MeshRuntime.edit_mesh，带 looptris不替代 Object.mode

设计选择

编辑态指针放 MeshRuntime，明确不存盘。保存前必须先转回数组。

常见误解

BMesh 不是第二种文件格式。磁盘上永远是 DNA Mesh。
