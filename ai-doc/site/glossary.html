词汇表

课里第一次出现的术语先在这里落地。每条一两句，链到首次使用的课。按主题分组，组内按出场顺序。

工具与读码

bpy

Blender 的 Python API 模块。官方二进制内置 Python 解释器，控制台里 import bpy 后，场景里几乎所有数据都能摸到。本路径的实验都靠它，不用编译。

首次使用：0.1 工具就位

Python 控制台

Blender 里的交互式解释器（Scripting 工作区，或任意区域切成 Console）。Ctrl+Space 补全，dir() 列成员。输入一行立刻看到结果，是观察设计的最近距离。

首次使用：0.1 工具就位

源码树

本仓库 checkout 出来的 Blender 源码。读码时主要逛三个目录：source/（主体）、intern/（Cycles 等内部库）、scripts/（Python UI）。

首次使用：0.1 工具就位；分工详表见 overview.md

符号

函数名、结构体名、宏名的统称。读码的基本功是「给一个符号，能在源码树里 grep 到它的定义」。课里所有英文标识符都是真实符号，可以在树里搜到。

首次使用：0.1 工具就位

数据块与 ID

数据块（data-block）

Blender 里「一个东西」的统称：物体、网格、材质、场景、相机……每个数据块开头都是同一个 ID 头，所以它们共享名字、用户计数、存盘规则。

首次使用：1.1 一切都是数据块

ID

每个数据块开头的公共结构（DNA_ID.h 的 struct ID）。里面有名字（前两字节是类型码，网格是 ME）、用户计数 us、脏标记 recalc、自定义属性 properties。

首次使用：1.1 一切都是数据块

用户计数（users）

ID 头上的整数：这份数据被几个地方引用。两个物体共用一份网格，网格的 users 就是 2。减到 0 的数据块才可能被清掉。

首次使用：1.1 一切都是数据块

伪用户（fake user）

数据块上的一个开关（bpy 里 use_fake_user）。打开后即使没人引用也存盘保留，防止「删掉最后一个使用者，数据块跟着消失」。

首次使用：1.1 一切都是数据块

孤儿数据块（orphan）

用户计数为 0 且没有伪用户的数据块。存盘时默认不写进去；bpy 里可用 bpy.data.orphans_purge() 立即清理。

首次使用：1.1 一切都是数据块

DNA 与文件

DNA

写进 .blend 的 C 结构布局，定义在 source/blender/makesdna/DNA_*_types.h。它只回答「这块内存怎么排」，不实现任何算法。磁盘上的真相。

首次使用：1.2 DNA 是磁盘布局

SDNA

构建期由 makesdna 工具扫描 DNA 头文件编出的「结构说明书」表。它既是当前进程的布局描述，也原样写进每个 .blend 的 DNA1 块，供旧版本对齐字段。

首次使用：1.2 DNA 是磁盘布局

.blend / DNA1

Blender 的存盘文件。里面按 DNA 布局顺序存所有数据块，末尾带 DNA1 块（这份文件用的 SDNA 表）。打开文件 = 按 DNA1 重建内存结构。

首次使用：1.2 DNA 是磁盘布局

runtime（运行时字段）

结构上明确不存盘的指针，例如 Mesh.runtime（MeshRuntime）。编辑态 BMesh、求值缓存都挂在这里。保存前必须能从中重建出纯 DNA 数据。

首次使用：1.2 DNA 是磁盘布局

RNA 与 Main

RNA

属性反射层：给 DNA 字段和运行时函数起对外名字、绑偏移、挂 update 回调。面板、Python bpy、Operator 属性都只认 RNA，不直接扫 C 结构体。

首次使用：1.3 RNA 是对外门面

bl_rna

bpy 里每个类型 / 实例都带的 RNA 自省入口。bpy.types.Mesh.bl_rna.properties 能列出 Mesh 对外暴露的全部属性——这就是 RNA 层在 Python 里的样子。

首次使用：1.3 RNA 是对外门面

Main

进程里全部数据块的数据库（BKE_main.hh 的 struct Main），按类型串起来的 ID 集合。bpy 里的 bpy.data 就是它的 Python 视图。一个 Blender 进程一份 Main。

首次使用：1.4 Main 与 Scene

Scene

「一幕场景」数据块：帧范围、渲染设置、当前 View Layer 指针等。它只是 Main 里的一块；一个文件可以有多个 Scene，bpy.context.scene 是用户正在看的那个。

首次使用：1.4 Main 与 Scene

操作符与事件

Operator

一次用户命令的封装：可撤销、可快捷键、可被 Python 点名（bpy.ops.*）。登记在 WM 的全局表里，键是 idname 字符串，值是带 poll / invoke / exec 回调的 wmOperatorType。

首次使用：2.1 Operator 是命令

poll / invoke / exec

操作符的三个回调：poll 答「现在能用吗」（否则菜单变灰）；invoke 答「怎么开始」（弹窗 / 直接跑 / 进模态）；exec 真正干活，不许碰界面输入，所以脚本直接调它。

首次使用：2.1 Operator 是命令

模态（modal）

操作符的一种运行方式：invoke 之后不结束，持续接管鼠标键盘事件（如移动、环切），直到确认或取消。由 modal 回调逐事件处理。

首次使用：2.1 Operator 是命令

宏操作符（macro）

把几个操作符串成一条登记（如「挤出 + 移动」）。执行时依次跑，撤销时仍是一条记录。

首次使用：2.1 Operator 是命令

键位映射（keymap）

「哪个键触发哪个操作符」的表，默认定义在 scripts/presets/keyconfig/keymap_data/blender_default.py。事件系统拿到按键先查它，再调对应操作符。

首次使用：2.1 Operator 是命令；完整链见 2.3 标脏与通知

update 回调

RNA 属性登记时挂的函数，赋值后被调用。它不改数据也不画图，只做标脏和发通知——例如 rna_Object_internal_update 只有一行 DEG_id_tag_update。

首次使用：2.2 属性链

标脏（tag）

在 ID 上打 ID_RECALC_* 标志（DEG_id_tag_update），告诉求值器「这份数据脏了，轮到求值时重算」。标脏本身不算任何东西。

首次使用：2.3 标脏与通知

通知（notifier）

发给界面的消息（WM_main_add_notifier），编码为 NC_* | ND_*：NC 是大类（几何 / 物体 / 场景），ND 是细分。订阅了这类消息的区域下次重画。

首次使用：2.3 标脏与通知

建模核心

BMesh

编辑态的网格表示：顶点 / 边 / loop / 面做成指针互连的网，邻接问题（这条边连着哪些面）按度数跳转就答完。不存盘，只活在编辑态和脚本里；Python 的 bmesh 模块是它的封装。

首次使用：3.1 两种网格表示

BMLoop（半边 / 面角）

一个顶点在一个面里的席位。面的 loop 串成环（BMFace.l_first），边的两侧面通过 loop 的 radial 环互找——「边的邻面」靠它回答。

首次使用：3.1 两种网格表示

编辑模式

Tab 进出是一次格式转换：进 = 数组 Mesh 转成 BMesh 挂到 Mesh.runtime->edit_mesh；出 = 写回 DNA。编辑期间的改动都打在 BMesh 上，DNA 保持旧值。

首次使用：3.3 编辑模式的进出

BMO（BMesh 操作符）

BMesh 层的几何算法表：输入一槽几何、输出一槽几何（如 extrude_face_region）。与 WM 操作符是两层——WM 管上下文和撤销，BMO 管算法；C 操作符和 Python bmesh.ops 调的是同一张表。

首次使用：3.4 挤出与 BMO

修改器（modifier）

挂在物体上的变形流水线节点。参数是 DNA（随文件存盘），变形留给求值：在原始网格的副本上跑 modify_mesh，原始数据不动。Apply 才把结果写回 DNA。

首次使用：3.5 修改器

求值副本（evaluated）

depsgraph 求值产出的物体 / 网格副本：obj.evaluated_get(dg) 拿到。修改器结果只在副本上；原始 ID 不动。阶段 4 的主角之一。

首次使用：3.5 修改器

求值与渲染

depsgraph（求值图）

把「谁依赖谁」编成图：标脏一块几何，事件循环空档只重算相关节点。视口和 F12 各用一张图（DAG_EVAL_VIEWPORT / DAG_EVAL_RENDER）。

首次使用：4.1 depsgraph 与求值副本

copy-on-eval（求值复制）

求值前把原始 ID 复制成求值副本的机制（5.x 源码 deg_eval_copy_on_write.*，旧称 copy-on-write）。修改器、驱动、矩阵都写在副本上，原始 ID 保持文件里的样子。

首次使用：4.1 depsgraph 与求值副本

overlay（叠加层）

视口最后叠上去的辅助显示层：网格线、选中描边、游标。它是 draw/engines/ 里的绘制引擎，但不是渲染引擎——F12 的引擎表里没有它。

首次使用：5.1 视口一帧

渲染引擎（RenderEngineType）

F12 可选的出图后端：EEVEE（BLENDER_EEVEE）、Workbench、Cycles。渲染管线通过统一接口 RE_engine_render 调它们，对链路上游透明。

首次使用：5.1 视口一帧；F12 链见 5.3 F12 链

视图变换（view transform）

渲染的线性数值到显示器之间的换算（默认 AgX），由 OpenColorIO 实现。只改显示，不改场景数据；设置在 Scene 的 view_settings / display_settings 上。

首次使用：5.5 颜色管理入门

专题（阶段 6）

字段（field）

几何节点里菱形接口流的「延迟函数」：不是一个值，而是「给个上下文（如某顶点位置）我算出对应值」。字段在被消费的那一刻按消费方的上下文批量求值，源码是 FN_field.hh 的 Field<T>。

首次使用：6.1 几何节点

几何节点（geometry nodes）

一个修改器（NodesModifierData，Constructive 型）：求值时把几何当数据过一遍节点树，输出新几何。不是 BMesh 替代，也不是独立模块——求值时机、Apply 语义全走修改器链。

首次使用：6.1 几何节点

合成器（compositor）

挂在 Scene 上的图像节点树（scene.node_tree，开关 use_nodes）。F12 链上引擎渲完后由 RE_compositor_execute 跑它；引擎管算图，合成管修图。另有视口实时合成的独立路径。

首次使用：6.2 合成

PBVH

雕刻的加速结构：把顶点按空间聚成叶节点的树，笔刷只遍历被刷到的几簇。三种后端——Mesh（普通）、Grids（多级细分）、BMesh（动态拓扑）。实现在 blenkernel/intern/pbvh.cc。

首次使用：6.3 雕刻

笔画（stroke / dab）

雕刻与绘制共用的 modal 框架（PaintStroke::modal）：鼠标移动按「间距」采样成一串落笔点（dab），每个 dab 调当前笔刷回调。所以脱手的脚本调不动笔画——它要鼠标上下文。

首次使用：6.3 雕刻

UV / 接缝（seam）

存在面角上的二维坐标（CD_PROP_FLOAT2，Mesh 的 uv_layers）。顶点共享、UV 不共享：相邻面的共用顶点 UV 不同就是一条接缝。展开（unwrap）是给所有面角求 (u, v) 的优化问题。

首次使用：6.4 UV 展开

顶点组 / 权重（vertex group / weight）

顶点域的稀疏数值：每个顶点带一串「（组编号，0–1 权重）」（MDeformVert / MDeformWeight）。数值存在 Mesh 上，组的名单存在 Object 的 vertex_groups 里——共享网格时数值共享、名单各自独立。骨骼修改器是最大消费方。

首次使用：6.5 权重与顶点组

约束（constraint）

叠在物体 / 骨骼变换上的规则（跟随、朝向、限位……），DNA 里是 bConstraint 链表。和修改器平行：修改器改几何，约束改变换；结果在 depsgraph 求值时算进 matrix_world，DNA 的 location 保持原值。

首次使用：6.6 约束

探针 / 光照缓存（light probe）

EEVEE 的预计算采样点：球（反射环境贴图）、平面（平面反射）、体积（辐照度栅格）。烘焙结果存光照缓存（LightProbeCache），是引擎运行时状态，不是场景几何。Cycles 路径追踪直接算间接光，不需要探针。

首次使用：6.7 EEVEE 探针

变换系统（transform）

G/R/S 背后的 modal 框架（editors/transform/）：invoke 后进 modal 循环，鼠标增量、数字直输、轴约束、吸附、比例编辑都是循环里的处理器。写回分两种：物体模式改 Object 的 TRS，编辑模式改 BMesh 顶点。

首次使用：6.8 变换系统

曲线 / Curves（两代）

老 Curve：Nurb 链表 + BezTriple（点带双手柄），文本对象也用它，可挤出倒角。新 Curves：属性域设计（点域 / 曲线域），为毛发和几何节点而生。bpy 里分两个集合：data.curves 与 data.hair_curves。

首次使用：6.9 曲线与 Curves

形态键（shape key）

网格顶点位置的另一份存储：Mesh 挂 Key 块，KeyBlock 链表第一个为 Basis，其余各存一份顶点数组，value 控制混入权重。求值时叠加到 Basis 上，原网格不动——表情与修形的标准工具。

首次使用：6.10 形态键
