UI 怎样碰到数据

UI 碰到数据只有两条入口：拖属性，或跑 Operator。下面用函数把两条链跟完。更细的走读在数据。

目录 模块 职责 功能 UI–数据 渲染地图

Python / C UI → RNA → Operator → BKE / DNA → notifier → depsgraph

链 A：拖属性

面板 layout.prop(mesh, "remesh_voxel_size") 不是把数字存进 Python。它点名 RNA 属性：

/* scripts/startup/bl_ui → C */
rna_uiItemR(layout, ptr, "remesh_voxel_size", ...)   /* rna_ui_api.cc */
  RNA_struct_find_property
  uiItemFullR / 控件绑定 PointerRNA

/* 用户改数字 */
RNA_property_*_set
  按 SDNA offset 写 Mesh.remesh_voxel_size
RNA_property_update
  prop->update 或默认 DEG_id_tag_update
  WM_msg_publish_rna / WM_main_add_notifier

所以面板上的数字几乎都是 RNA 属性，绑定 DNA 字段或 getter/setter，不是另一份平行数据。

链 B：跑 Operator

菜单和快捷键指向 wmOperatorType（WM_operatortype_append）。真正改网格的是 editors 里的 exec，不是 bl_ui。

WM_main
  wm_event_do_refresh_wm_and_depsgraph   /* 先求值再跑命令 */
  wm_window_events_process
  wm_event_do_handlers
    wm_operator_invoke
      poll → invoke / exec
  wm_event_do_notifiers
  wm_draw_update

Python bpy.ops.mesh.subdivide() 走 WM_operator_call_py，仍进同一套 invoke，不另开一条改网格的路。

改完谁知道

视口不会轮询每个顶点。DEG_id_tag_update 告诉 depsgraph 重算；WM_main_add_notifier 告诉编辑器重画。带 OPTYPE_UNDO 的命令再 ED_undo_push_op。

和建模的衔接

编辑模式多一个台阶：Operator → BMesh → EDBM_update 标脏。写回 DNA 发生在退出或 flush。物体模式没有这一步。细节归建模。

和邻居的边界

入口写谁不写谁
layout.propDNA 字段 + updateBMesh 拓扑
layout.operator / 快捷键editors execbl_ui 自己的网格
notifier编辑器重画不跑修改器

设计选择

两条入口，同一条尾巴：标脏 + 通知。Operator 额外推撤销。

常见误解

看到 bl_ui 就以为 UI 用 Python 改网格。它只点名属性和 Operator。
