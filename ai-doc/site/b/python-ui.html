面板只画，不改顶点

bl_ui 注册 Panel / Menu。 layout.prop 和 layout.operator 是 C 里的 RNA 函数（rna_ui_api.cc → rna_uiItemR / rna_uiItemO）。点下去分别变成「写属性」或「叫 Operator」。

数据入口 DNA RNA Python UI Operator / WM 更新与撤销

它解决什么

bl_ui 只负责「这块屏幕画哪些控件」。改数据的两条出口已经定死：layout.prop 写 RNA，layout.operator 提交命令。面板文件里几乎没有顶点循环。

Mesh 属性面板

scripts/startup/bl_ui/properties_data_mesh.py。基类定空间：属性编辑器、数据上下文。 poll 要求 context.mesh 存在。

class MeshButtonsPanel:
    bl_space_type = 'PROPERTIES'
    bl_region_type = 'WINDOW'
    bl_context = "data"

    @classmethod
    def poll(cls, context):
        return context.mesh and (context.engine in cls.COMPAT_ENGINES)

class DATA_PT_remesh(MeshButtonsPanel, Panel):
    def draw(self, context):
        mesh = context.mesh
        col.prop(mesh, "remesh_voxel_size")      # 链 A：写 RNA
        col.operator("object.voxel_remesh")      # 链 B：提交 Operator

同一面板里两条出口并排：数字走属性，按钮走命令。体素尺寸还可带 PROP_NO_DEG_UPDATE，等你按 Remesh 再算。

context.mesh 不是 Context 上的静态 RNA 字段。属性编辑器 editors/space_buttons/buttons_context.cc 的 buttons_context() 沿 Scene → Object → ob->data 填 "mesh"。C 侧 CTX_data_pointer_get(C, "mesh") / ED_mesh_context()。

View3D 菜单

scripts/startup/bl_ui/space_view3d.py 的 VIEW3D_MT_view：layout.prop(view, "show_region_toolbar") 改空间数据；layout.operator("view3d.view_selected") 只提交 Operator 名。头栏 VIEW3D_MT_editor_menus 再 layout.menu("VIEW3D_MT_view")。

按钮按下之后

editors/interface/interface.cc 的 button_value_set → RNA_property_float_set 等。收尾在 interface_handlers.cc 调 RNA_property_update。Operator 按钮走 WM_operator_name_call_ptr_with_depends_on_cursor。

Python 里也有 Operator

scripts/startup/bl_operators/（mesh.py 等）用 bl_idname + execute 注册，和 C 的 MESH_OT_* 同一套 WM 表。编辑模式大部分细分/挤出仍是 C。

和邻居的边界

Python 文件角色不负责
bl_ui/properties_data_mesh.py画 Mesh 面板改 BMVert
bl_ui/space_view3d.py菜单与着色模式开关求值修改器
bl_operators/mesh.py少数 Python Operator替代 MESH_OT_* 主路径

设计选择

上下文里的 mesh 由属性编辑器现场填充，不是 Context 上的死字段。

常见误解

看到 bl_ui 就以为 UI 用 Python 改网格。它只点名属性和 Operator。
