DNA：磁盘上的真相

每个数据块是带 ID 头的 C 结构。makesdna 在构建期扫描 DNA_*_types.h，编成 SDNA 表；这份表既是当前进程布局，也写进每个 .blend 的 DNA1 块。

数据入口 DNA RNA Python UI Operator / WM 更新与撤销

它解决什么

编辑器和渲染器都需要一份能存盘、能跨版本打开的对象。DNA 只回答「这块内存怎么排」：名字、用户计数、顶点数、属性层。它不实现挤出，也不画像素。

  1. 头文件声明 struct Mesh 这类 C 布局。
  2. 构建工具扫头文件，编成当前进程的 SDNA 表。
  3. 写 .blend 时把同一份表放进 DNA1，读文件时按成员对齐旧布局。

Mesh 从 ID 开始

source/blender/makesdna/DNA_mesh_types.h。verts_num / CustomData / AttributeStorage 会进文件。后面的 MeshRuntime *runtime（含编辑态 BMesh）明确不存盘。

struct Mesh {
  ID id;
  AnimData *adt;
  Material **mat;
  int verts_num, edges_num, faces_num, corners_num;
  AttributeStorage attribute_storage;
  CustomData vert_data, edge_data, face_data, corner_data;
  /* ... flags, remesh_*, symmetry ... */
  /* MeshRuntime *runtime  -- not DNA */
};

DNA_ID.h 的 ID：名字（前两字节类型码 ID_ME）、用户计数 us、recalc（给 depsgraph / undo）、properties。

读文件时怎么对上旧版本

  1. 构建：makesdna/intern/makesdna.cc 扫头文件 → DNAstr 二进制。
  2. 运行时：DNA_sdna_current_get()（dna_genfile.cc）解码当前布局。
  3. 打开文件：BLO_read_from_file → blo_read_file_internal。看到 DNA1 后 read_file_dna：DNA_sdna_from_data，再 DNA_struct_get_compareflags。
  4. 字段没变就 memcpy；变了就 DNA_struct_reconstruct 按成员拷（增删改名靠 dna_rename_defs.h）。

所以 DNA 不是「游戏场景树」，是「可版本对齐的结构体数据库」。加载结果是 Main 里的 ID 链表，见 blenloader。

/* dna_genfile.cc */
DNA_sdna_from_data(data, ...)     /* 解码文件或当前进程的 SDNA */
DNA_struct_get_compareflags(...)
DNA_struct_reconstruct(...)       /* 字段变了按成员拷 */

/* blenloader */
BLO_read_from_file → blo_read_file_internal
  看到 DNA1 → read_file_dna → 上面两套对齐 */

和邻居的边界

层它写什么它不写什么
DNAC 结构布局、SDNA 表、.blend 里的 DNA1属性显示名、挤出算法、像素
RNA对外名字、offset、update磁盘字段顺序
BMesh编辑态半边，挂在 MeshRuntime不进文件

按钮不直接 mesh->remesh_voxel_size = x。它拿的是 RNA 属性；RNA 再按 SDNA offset 写这个字段。

设计选择

把「磁盘布局」和「对外名字」拆开，换 RNA 名不必改文件格式。

常见误解

DNA 不是游戏场景树。加载结果是 Main 里的 ID 链表。
