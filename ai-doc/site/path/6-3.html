6.3 雕刻：PBVH 与笔画

雕刻不用 BMesh。它有自己的加速结构 PBVH（把网格切成一簇簇叶节点，笔刷只摸被刷到的那几簇），和一条自己的笔画管线：鼠标事件 → 采样 → 笔刷回调 → 顶点位移。这就是为什么百万顶点也能实时刷。

路径索引 6.1 几何节点 6.2 合成 6.3 雕刻 6.4 UV 6.5 权重 6.6 约束 6.7 EEVEE 探针 6.8 变换 6.9 曲线 6.10 形态键

目标

  • 说出雕刻为什么不用 BMesh：要的是局部高速读写，不是拓扑编辑。
  • 认识 PBVH 的三种后端：Mesh / Grids（多级细分）/ BMesh（动态拓扑）。
  • 用 bpy 进雕刻模式、查看当前笔刷；知道笔画本身要鼠标上下文。

概念：另一套编辑世界

阶段 3 的编辑模式是「拓扑手术」：选顶点、挤出、溶解，BMesh 半边结构维护拓扑合法性。雕刻是「批量推拿」：一笔下去成千上万个顶点沿法向位移，拓扑通常不变，要的是快。

  • PBVH：把顶点按空间聚成叶节点的树。笔刷落下时只遍历被刷圈碰到的叶节点，其余顶点零成本。
  • 三种后端：普通网格（Mesh）、多级细分（Grids，刷的是细分后的栅格）、动态拓扑（BMesh——唯一会改拓扑的雕刻模式，dyntopo）。
  • 笔画管线：雕刻/绘制共用一个 modal 笔画框架——鼠标移动被按「间距」采样成一串 dab（落笔点），每个 dab 调当前笔刷的回调。

源码走读：从笔画到 PBVH

  • 笔画框架：editors/sculpt_paint/paint_stroke.cc:1398 的 PaintStroke::modal——雕刻、顶点色、权重绘制共用这条 modal 循环。
  • 雕刻代码家：source/blender/editors/sculpt_paint/（网格雕刻在 mesh/ 子目录，笔刷在 mesh/brushes/）。
  • PBVH 实现：source/blender/blenkernel/intern/pbvh.cc——建叶节点 build_mesh_leaf_nodes（:81），遍历器 PBVHIter（:678）。
  • 三种后端的分叉：sculpt_ops.cc:105 按 bke::pbvh::Type::Mesh / Grids / BMesh 分派——对应普通雕刻、多级细分、动态拓扑。

所以 Q024 说雕刻「和 BMesh 编辑不是同一套」：别在 sculpt_paint/ 里找挤出，也别在 editors/mesh/ 里找笔刷。

动手实验：进雕刻模式看笔刷

官方二进制控制台逐段执行（默认立方体即可）：

import bpy
bpy.ops.object.mode_set(mode='SCULPT')
bpy.context.active_object.mode
# 预期：'SCULPT' —— 模式是 Object 上的标志（回看 2.1）
sculpt = bpy.context.tool_settings.sculpt
sculpt.brush.name
# 预期：当前笔刷名，如 'Draw'
sorted(b.name for b in bpy.data.brushes if b.use_paint_sculpt)
# 预期：雕刻可用笔刷清单 —— Clay / Draw / Grab / Smooth …
sculpt.brush.strength = 0.3
sculpt.brush.size
# 预期：强度改了、半径可读 —— 笔刷参数是普通 RNA 属性（2.2 的链）

边界提示：真正的笔画（bpy.ops.sculpt.brush_stroke）需要鼠标位置和视口上下文，控制台直接调多半报上下文错误——这是有意设计：笔画由 PaintStroke::modal 驱动，不是脱手脚本接口。想看效果，在 3D 视口用鼠标刷几笔，再回控制台对比 len(me.vertices) 没变（普通雕刻不动拓扑）。

bpy.ops.object.mode_set(mode='OBJECT')
