3.1 两种网格表示

同一份几何有两副面孔：存盘和求值用数组 Mesh（按下标访问），编辑操作用指针网 BMesh（按邻接跳转）。这节课弄清谁适合什么。

路径索引 2.3 标脏与通知 3.1 两种表示 3.2 玩 BMesh

目标

  • 说出数组 Mesh 与 BMesh 各自的强项：为什么一份几何要两种表示。
  • 在控制台里对同一块立方体，分别用两种表示回答「邻接」问题。

概念：数组答不动「这个面的邻面」

1.2 说过 Mesh 是 DNA——磁盘布局。它的几何是三摞平面数组：顶点数组、边数组、面（面角）数组，全靠下标。面只知道「我的顶点是 0、1、2、3 号」，边只知道「我连着 v1、v2」。紧凑、好序列化、好喂给 GPU——存盘、求值、渲染都爱它。

但编辑操作问的是另一类问题：「这条边连着哪些面？」「这个顶点的所有邻边？」「这个面的邻面？」数组只能全表扫描。BMesh 把同样几类元素做成指针互连的网：每个顶点带着一条出发边的指针，每条边带着两端点和面环指针，每个面带着 loop 环。邻接问题按度数跳转就答完，不用扫表。代价：指针不存盘、占内存、要维护一致性——所以只活在编辑态。

关键角色 BMLoop（半边 / 面角）：一个顶点在一个面里的席位。同一条边两侧的面，通过各自 loop 的 radial 环互相找到——「边的邻面」就是这么答的。

源码走读：两种表示的结构定义

数组侧：DNA_mesh_types.h 的 struct Mesh（:147），几何规模就是四个计数——verts_num（:168）、edges_num（:170）、faces_num（:172）、corners_num（:174）。

指针网侧：source/blender/bmesh/bmesh_class.hh：

struct BMVert { ... float co[3];  /* :94，坐标 :97 */
                BMEdge *e; }        /* :107 任一邻边，disk cycle 的起点 */
struct BMEdge { ... BMVert *v1, *v2;/* :124，端点 :135 */
                BMLoop *l; }        /* :141 绕边的面环（radial） */
struct BMLoop { ... BMVert *v;      /* :158，这个角用哪个顶点 :165 */
                BMEdge *e; BMFace *f; } /* :177 / :184 */
struct BMFace { ... BMLoop *l_first;/* :277，loop 环入口 :285 */
                int len; }          /* :291 几个角 */

注意 BMVert 只存「一条」邻边（e），其余邻边靠 disk cycle 环着找——指针网的设计处处是「存一个入口，跳转答全部」。

动手实验：同一块立方体，两种问法

默认场景选中立方体，控制台逐段执行：

import bpy, bmesh
me = bpy.context.object.data
len(me.vertices), len(me.edges), len(me.polygons)
# 预期：(8, 12, 6) —— 数组表示：三个数描述完规模

me.polygons[0].vertices[:]
# 预期：[0, 1, 2, 3] 一类 —— 面只存顶点下标，邻接要自己算
bm = bmesh.new()
bm.from_mesh(me)                  # DNA → BMesh（转换初体验）
bm.verts.ensure_lookup_table()
v = bm.verts[0]
[e.index for e in v.link_edges]   # 顶点的邻边，直接问
# 预期：[0, 3, 4] 一类 —— 不用扫全表

bm.faces.ensure_lookup_table()
[l.vert.index for l in bm.faces[0].loops]  # 面的 loop 环
# 预期：四个顶点下标，按顺序
bm.free()

对照体会：数组那边「面 → 顶点下标」是一步，「顶点 → 邻边」要写循环扫 12 条边；指针网这边两个方向都是一步跳转。
