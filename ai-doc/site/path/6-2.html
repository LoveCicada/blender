6.2 合成：渲染出图之后的节点树

F12 并不在引擎写完像素就结束——渲染管线最后还有一道合成：把引擎写出的 Render Result 过一遍合成节点树，再交回图像编辑器。辉光、调色、去噪后处理都发生在这里，跟渲染引擎无关。

路径索引 6.1 几何节点 6.2 合成 6.3 雕刻 6.4 UV 6.5 权重 6.6 约束 6.7 EEVEE 探针 6.8 变换 6.9 曲线 6.10 形态键

目标

  • 在 F12 链上指出合成环节的位置：引擎之后、写盘之前。
  • 用 bpy 打开合成并插一个调色节点，重渲染看效果。
  • 知道视口合成器的存在（实时、独立于 F12）。

概念：引擎管算，合成管修

分工一句话：渲染引擎把场景算成图像，合成器把图像修成成品。

  • 合成节点树挂在 Scene 上（scene.node_tree），开关是 scene.use_nodes——和材质节点树完全独立。
  • 输入通常是「渲染层」（Render Layers）节点：拿到引擎刚写出的通道（颜色、深度、法向……）；终点是 Composite 节点：结果写回 Render Result。
  • 因为发生在引擎之后，改合成节点不用重渲染场景——但 F12 会连引擎带合成完整跑一遍。
  • 视口还有一个实时合成器（Compositor 面板里开），走的是另一条交互式路径，本课只点名。

源码走读：管线里的合成钩子

  • 开关的 RNA：rna_scene.cc:9556 的 use_nodes（Scene 上的布尔）。
  • F12 链上的调用点：pipeline.cc:1380——引擎渲完后调 RE_compositor_execute（声明在 RE_compositor.hh:54，实现 render/intern/compositor.cc:906）。
  • 视口交互式合成：pipeline.cc:536 的 RE_NewInteractiveCompositorRender——独立于 F12 的另一条链。
  • 合成器本体：source/blender/compositor/（算法、缓存资源、着色器都在这）；节点实现一节点一文件，如亮度对比 nodes/composite/nodes/node_composite_brightness_contrast.cc。

对照 5.3 的链：RENDER_OT_render → RE_RenderFrame → RE_engine_render，合成就接在 RE_engine_render 返回之后——所以 Q192 说「不要在 Cycles kernel 里找 Glare 节点实现」。

动手实验：给渲染图加一道亮度节点

官方二进制控制台逐段执行（场景里保留默认立方体+灯光即可）：

import bpy
scene = bpy.context.scene
scene.use_nodes
# 预期：False（默认场景没开合成）
scene.use_nodes = True
[(n.name, n.bl_idname) for n in scene.node_tree.nodes]
# 预期：自动建好两节点 —— Render Layers + Composite
nt = scene.node_tree
rl = next(n for n in nt.nodes if n.bl_idname == "CompositorNodeRLayers")
comp = next(n for n in nt.nodes if n.bl_idname == "CompositorNodeComposite")
bc = nt.nodes.new("CompositorNodeBrightContrast")
bc.inputs["Bright"].default_value = 20.0
nt.links.new(rl.outputs["Image"], bc.inputs["Image"])
nt.links.new(bc.outputs["Image"], comp.inputs["Image"])
# 预期：节点编辑器里亮度节点插进了 Render Layers → Composite 之间
bpy.ops.render.render()
# 预期：渲完的 Render Result 明显变亮 —— 引擎没改，是合成节点动了像素

收尾验证「合成独立于引擎」：把 bc.mute = True 再 F12，亮度消失——同一引擎输出，合成树说了算。
