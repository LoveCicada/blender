6.10 形态键：顶点位置的另一份存储

形态键（shape key）给网格存了另一套顶点位置：Basis 是参考形，其余每个键各存一份完整顶点数组，value 滑条控制混入权重。原网格顶点始终不动——又一条「DNA 存参数，求值算结果」的链，和修改器、约束是同一思想。

目标

  • 说出形态键的存储结构：Key 块挂 Mesh，KeyBlock 链表各存一份顶点位置。
  • 用 bpy 建 Basis + 一个键，改坐标、调 value，验证原网格不动。
  • 解释形态键与修改器的异同，以及为什么动画用形态键。

概念：按权重混入的顶点数组

  • 存储：Mesh 上挂一个 Key 数据块，里面是 KeyBlock 链表。第一个永远是 Basis（参考形）；其余每个键存一份和网格顶点一一对应的坐标数组。
  • 混合：每个键有 value（0–1，可超界）。求值时把各键按权重叠加到 Basis 上，算出最终顶点位置——多个键可以同时生效（挑眉 + 张嘴）。
  • 非破坏：me.vertices 永远是建模态的原始位置；形态键的结果只在求值后出现。所以它能做动画：给 value 打关键帧即可，不用动网格。
  • 对照修改器：都是「求值时算结果」；区别在于形态键不改拓扑、只存顶点位置，且专为「几个离散形态之间插值」设计——表情、修形的标准工具。

源码走读：Key、KeyBlock 与求值

  • DNA：DNA_key_types.h——KeyBlock（:70，链表节点，内含坐标数组与 value）、Key（:108，块本体）。
  • 挂在 Mesh 上：DNA_mesh_types.h:158 的 struct Key *key；RNA 入口 rna_mesh.cc:3321 的 shape_keys。
  • 创建入口：rna_object_api.cc:1116 的 shape_key_add（bpy 方法；实现 :476）。
  • 求值：blenkernel/intern/key.cc:1133 的 BKE_key_evaluate_object——按权重算出最终坐标数组。

动手实验：建键、改形、验证原网格不动

官方二进制控制台逐段执行（默认立方体）：

import bpy
ob = bpy.context.active_object
me = ob.data
ob.shape_key_add(name='Basis')
sk = ob.shape_key_add(name='Up')
[kb.name for kb in me.shape_keys.key_blocks]
# 预期：['Basis', 'Up'] —— 第一个是参考形
kb = me.shape_keys.key_blocks['Up']
kb.data[5].co.z += 1.0
# 预期：视口还看不出变化 —— value 默认 0，权重为零
kb.value = 1.0
tuple(round(v, 2) for v in me.vertices[5].co)
# 预期：原值不变（约 (1, 1, 1)）—— 动的是形态键的存储，不是网格
dg = bpy.context.evaluated_depsgraph_get()
ev = ob.evaluated_get(dg).data
tuple(round(v, 2) for v in ev.vertices[5].co)
# 预期：z 多了 1.0 —— 求值后的副本上才是混入结果

收尾：kb.value = 0.0。这条实验链把阶段 1（DNA 存储）、阶段 4（求值副本）、本课（形态键）串成了一条线。
