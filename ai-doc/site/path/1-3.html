1.3 RNA 是对外门面

DNA 管磁盘布局；RNA 管对外：给字段起名字、定类型、挂回调。面板上的滑条、bpy 里的属性、Operator 的参数，全都只认 RNA，不直接摸 C 结构体。

路径索引 1.2 DNA 1.3 RNA 1.4 Main 与 Scene

目标

  • 说出 DNA 与 RNA 的分工：一个管「怎么存」，一个管「对外叫什么、改了通知谁」。
  • 会用 bl_rna 自省：在控制台里翻出一个类型的全部对外属性。

概念：为什么要多一层

1.2 课的 verts_num 是 C 结构体成员，界面和脚本没法直接安全地摸它：名字可能改、类型可能换、改了之后还要通知界面刷新。RNA 就是中间这层门面：

  • 给字段起对外名字（标识符 + 显示名），内部成员改名不影响文件和脚本。
  • 声明类型与范围：浮点、枚举、集合，滑条的最小最大值。
  • 挂 update 回调：属性被改后该标脏谁、刷新谁（阶段 2 的主角）。

所以同一份数据有三个名字：C 成员名（DNA）、RNA 标识符（bpy 里用的）、显示名（界面上看到的）。这门课实验里你会一次看到三个。

源码走读：Mesh 的 RNA 注册

source/blender/makesrna/intern/rna_mesh.cc:2935 的 rna_def_mesh：

srna = RNA_def_struct(brna, "Mesh", "ID");   /* :2940  RNA 类型 Mesh 继承 ID */
prop = RNA_def_property(srna, "vertices", PROP_COLLECTION, PROP_NONE);  /* :2944 */
RNA_def_property_collection_funcs(prop,
    "rna_Mesh_vertices_begin", ..., "rna_Mesh_vertices_length", ...);
RNA_def_property_ui_text(prop, "Vertices", "Vertices of the mesh");

逐行对照："Mesh", "ID" 呼应 1.1 课的「开头都是 ID」；"vertices" 是 bpy 里的标识符；"Vertices" 是界面显示名；真正读数据的是 rna_Mesh_vertices_* 这组 C 函数。属性不是字段别名，是一组访问函数。

动手实验：在控制台里翻 RNA

import bpy
props = bpy.types.Mesh.bl_rna.properties
len(props)
# 预期：几十（Mesh 对外暴露的全部属性）
[p.identifier for p in props][:8]
# 预期类似：['name', 'users', 'use_fake_user', ..., 'vertices', ...]
# 注意前三个正是 1.1 课 ID 头里的东西 —— RNA 类型继承 ID
p = props["vertices"]
p.name          # 预期：'Vertices'（显示名）
p.identifier    # 预期：'vertices'（bpy 标识符）
p.type          # 预期：'COLLECTION'

再对照源码：rna_mesh.cc:2944 注册的正是这个 "vertices"。控制台里翻到的每一项，都能在这样某个 rna_*.cc 里找到注册点。

me = bpy.context.object.data
len(me.vertices)     # 走的就是 rna_Mesh_vertices_length 那组 C 函数
