5.3 F12 链

按 F12 走的不是视口那条路：一个普通操作符 RENDER_OT_render 起头，渲染管线自建 DAG_EVAL_RENDER 图（4.2），再把帧交给当前引擎。链：RENDER_OT_render → RE_RenderFrame → RE_engine_render。

路径索引 5.2 EEVEE 5.3 F12 链 5.4 Cycles

目标

  • 背出 F12 的三段链，并指出每段的文件。
  • 说出视口一帧与 F12 的分道点：哪一步开始不再是视口那条路。
  • 用 bpy 渲染出图，并换引擎对比。

概念：分道点在「自建图」

视口一帧（5.1）：事件循环 → 求值视口图 → Draw Manager 画到屏幕区域。F12 是另一条路：

  1. 操作符：F12 / 菜单 / bpy.ops.render.render() 都进 RENDER_OT_render——2.1 的表在这里又出现了。
  2. 管线建图：渲染管线为这一帧自建一张 DAG_EVAL_RENDER 模式的 depsgraph（4.2：级别、可见性全按渲染档），算完即弃。
  3. 引擎出帧：RE_engine_render 把求值结果交给当前引擎（EEVEE / Workbench / Cycles），引擎逐块出图，写进 Render Result。

分道点就在第 2 步：视口复用常驻的视口图，F12 自建渲染图。这也是为什么 F12 可以比视口「更光滑」（4.2 的两个级别字段）。

源码走读：三段各在哪

  • 操作符：RENDER_OT_render 登记在 editors/render/render_internal.cc:1031（idname :1037）。
  • 帧入口：RE_RenderFrame 在 render/intern/pipeline.cc:2011；渲染图建在 :1977（DEG_graph_new(..., DAG_EVAL_RENDER)）。
  • 引擎出帧：RE_engine_render 在 render/intern/engine.cc:1007，由 RE_RenderFrame 调用（:2129）。

动手实验：bpy 渲染并换引擎

默认立方体场景，控制台逐段执行：

import bpy
bpy.ops.render.render(write_still=True)
# 预期：渲染窗口出图；write_still 把图写到输出路径
# （输出路径见 bpy.context.scene.render.filepath）
bpy.context.scene.render.engine = 'BLENDER_WORKBENCH'
bpy.ops.render.render(write_still=True)
# 预期：同一场景，Workbench 风格 —— 链不变，换的是最后一环的引擎
bpy.context.scene.render.engine = 'BLENDER_EEVEE'
# 渲染完记得切回来

体会：三段链对引擎是透明的——RE_engine_render 面向「引擎接口」工作，EEVEE / Workbench / Cycles 都是接口的实现。
