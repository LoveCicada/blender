6.8 变换系统：G/R/S 背后的 modal 框架

建模最高频的操作——移动、旋转、缩放——不是三个独立工具，而是同一个 modal 框架的三个模式。一次 G 键：进 modal、鼠标增量、数字直输、轴约束、确认或取消，全由 editors/transform/ 一套代码驱动。它还是「同一操作，两种写回」的典型：物体模式写 Object 的 TRS，编辑模式写 BMesh 顶点。

路径索引 6.1 几何节点 6.2 合成 6.3 雕刻 6.4 UV 6.5 权重 6.6 约束 6.7 EEVEE 探针 6.8 变换 6.9 曲线 6.10 形态键

目标

  • 说出 G/R/S 是同一 Operator 家族的不同模式，共用一条 modal 循环。
  • 解释变换的两种写回：物体模式改 TRS，编辑模式改顶点。
  • 认识 modal 期间的修饰系统：数值输入、轴约束、吸附、比例编辑。

概念：一次 G 键的旅程

2.1 讲过 Operator 的 poll / invoke / exec；变换是modal 用法的教科书案例：

  • invoke：记下起点、选中集，进入 modal——此后鼠标键盘事件都喂给它。
  • modal 循环：鼠标移动转成增量；敲 X/Y/Z 锁轴；敲数字直接进入「数值输入」状态（标题栏实时显示）；Tab 之外的修饰键随时改行为。
  • 确认 / 取消：左键或回车把增量写回；右键或 Esc 整体回滚——modal 期间的数据改动都是临时的。
  • 两种写回：物体模式把结果写进 Object 的位置/旋转/缩放（标 TRANSFORM 脏）；编辑模式直接动 BMesh 顶点（走 2.3 的 EDBM_update 链）。所以 Q051 说「物体模式移动立方体不进 BMesh」。
  • 修饰系统：吸附（snap）把增量对齐到栅格/顶点；比例编辑（proportional editing）让选中点带着周围按衰减曲线一起动——都是 modal 循环里的可选处理器。

源码走读：一个家族，一张表

  • idname 与注册：transform_ops.cc:59 的 OP_TRANSLATION 常量，:102 的表把各 idname 映射到 TFM_* 模式——G/R/S 只是同框架的三个条目。
  • Operator 定义：transform_ops.cc:850 的 TRANSFORM_OT_translate；:861 把 ot->modal 挂到 :412 的 transform_modal——所有变换模式共用的主循环。
  • modal 键位表：transform.cc:825 的 transform_modal_keymap——modal 期间「哪个键锁轴、哪个键切吸附」在这登记。
  • 修饰开关的 RNA：rna_scene.cc:3721 的 proportional_edit、:3879 的 use_snap（都在 ToolSettings 上）。

动手实验：无鼠标的一次变换

modal 操作也能脚本化——exec 路径直接吃参数（2.1 的原则：exec 不碰界面输入）。官方二进制控制台逐段执行：

import bpy
ob = bpy.context.active_object
tuple(ob.location)
# 预期：当前位置，如 (0.0, 0.0, 0.0)
bpy.ops.transform.translate(value=(1, 0, 0))
tuple(ob.location)
# 预期：(1.0, 0.0, 0.0) —— 没进 modal：给了 value 直接 exec 写回
ts = bpy.context.tool_settings
ts.use_snap = True
ts.snap_elements
# 预期：吸附元素集合（如 {'INCREMENT'}）—— modal 循环里查的就是这些标志
ts.proportional_edit = 'ENABLED'
ts.proportional_edit_falloff
# 预期：'SMOOTH' 一类 —— 比例编辑的衰减曲线类型
ts.proportional_edit = 'DISABLED'
ts.use_snap = False
# 收尾：恢复默认

对照实验：进编辑模式全选顶点，再 bpy.ops.transform.translate(value=(0, 0, 1))——这次动的是 BMesh 顶点，ob.location 不变。同一 Operator，两种写回。
