6.4 UV 展开：面角上的另一份数据

UV 不是顶点的属性，是面角（loop）的属性：立方体 8 个顶点却有 24 份 UV——同一个顶点在相邻面上可以占纹理的不同位置，接缝就是这么来的。展开（unwrap）则是把 3D 表面摊平成 2D 坐标的算法活。

路径索引 6.1 几何节点 6.2 合成 6.3 雕刻 6.4 UV 6.5 权重 6.6 约束 6.7 EEVEE 探针

目标

  • 解释 UV 为什么存在面角上而不是顶点上（接缝的必要性）。
  • 用 bpy 读写 UV 数据，亲手验证「8 顶点、24 份 UV」。
  • 知道展开 Operator 的源码位置与上下文要求。

概念：顶点共享，UV 不共享

3D 里一个顶点被几个面共用是好事（省内存、平滑法向）。但贴图时，同一个顶点在不同面上可能要落在纹理的不同位置——比如立方体的一条棱，左右两个面在纹理上往往不挨着。解决办法：UV 按面角存。

  • 每个面有 N 个面角（loop），每个面角存一份二维 (u, v)。立方体 6 面 × 4 角 = 24 份。
  • 相邻面的共用顶点若 UV 值相同，纹理在那里连续；不同，就是一条接缝（seam 的视觉来源）。
  • 这就是 3.1 说的「面角层数据」的又一个实例：顶点色、UV、蒙皮权重里的环数据都挂在 loop 域。
  • 展开（unwrap）= 给所有面角求一组 (u, v)，尽量保面积、少拉伸——是数值优化问题，不是拓扑操作。

源码走读：属性、RNA 与展开

  • UV 的存储类型：rna_mesh.cc:1698 附近可见 UV 层是 CD_PROP_FLOAT2——每个面角一个二维浮点，走 CustomData / 属性体系（Q019）。
  • RNA 入口：rna_mesh.cc:3116 的 uv_layers（Mesh 上的集合属性，可有多套 UV）。
  • UV 编辑器代码家：source/blender/editors/uvedit/——选区、孤岛（island）、展开都在这。
  • 展开 Operator：uvedit_unwrap_ops.cc:3011 的 UV_OT_unwrap（idname 在 :3029）——就是编辑模式下按 U 弹出的那个 Unwrap。

动手实验：数清 24 份 UV

官方二进制控制台逐段执行（默认立方体，物体模式即可）：

import bpy
me = bpy.context.active_object.data
uv = me.uv_layers.active or me.uv_layers.new(name="UVMap")
len(me.vertices), len(me.loops), len(uv.data)
# 预期：(8, 24, 24) —— UV 份数跟着 loop 走，不跟顶点走
uv.data[0].uv
# 预期：Vector((x, y)) —— 第一份面角的二维坐标
poly = me.polygons[0]
[(li, round(uv.data[li].uv.x, 3), round(uv.data[li].uv.y, 3)) for li in poly.loop_indices]
# 预期：第一个面的 4 个面角各一份 UV —— 面角索引就是 uv.data 的索引
uv.data[0].uv = (0.0, 0.0)
# 预期：UV 编辑器里对应角跳到原点 —— 直接写属性就生效（标脏链见 2.3）

边界提示：bpy.ops.uv.unwrap() 要求编辑模式 + 选中面 + 合适的区域上下文，控制台裸调多半报 context 错误。想走完整链：3D 视口 Tab 进编辑模式、A 全选、U → Unwrap，然后回控制台重跑上面的读取，对比展开前后的 UV 值。
