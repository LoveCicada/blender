6.7 EEVEE 探针与光照缓存

光栅化引擎每像素只知道直接光，间接光和镜面反射不会凭空出现——探针是场景里预计算的「采样点」：把反射和漫反射间接光先算好存成缓存，着色时查表。这就是为什么探针是 EEVEE 专属：Cycles 的路径追踪直接算，不需要这套缓存。

目标

  • 说出探针解决什么：光栅引擎没有免费的间接光与反射。
  • 认识三种探针：球（反射）、平面（平面反射）、体积（辐照度网格）。
  • 用 bpy 添加探针；说清探针数据是引擎缓存，不是场景几何。

概念：预计算，着色时查表

5.2 说过 EEVEE 是光栅化：每个像素着色时，能直接算的只有「光源 → 表面 → 相机」这一条路。镜面里看到旁边的物体、墙面反弹的光——这些要多跳路径，光栅化做不到。探针是妥协方案：

  • 球探针（Sphere）：在一点把周围场景渲成环境贴图，附近的光滑表面拿它当反射。
  • 平面探针（Plane）：给镜面、地板这类平面反射单独渲一份。
  • 体积探针（Volume）：在空间撒一张 3D 栅格，每格存漫反射间接光（辐照度），物体走过时插值查表。
  • 算出来的结果存进光照缓存（light probe cache）——它是引擎的运行时数据，可以自动/手动烘焙，不是 DNA 网格，删掉探针物体缓存就没了来源。

对照 Cycles：路径追踪逐像素多跳采样，间接光是「算出来的」不是「存起来的」，所以 Cycles 面板里没有探针——Q178 说的「光栅引擎状态」就是这个意思。

源码走读：DNA、Operator 与引擎模块

  • 探针的 DNA：DNA_lightprobe_types.h:115 的 LightProbe；类型枚举 :29–31——SPHERE / PLANE / VOLUME 三种。
  • 缓存结构：同文件 :194 的 LightProbeCache——烘焙结果的容器。
  • 添加 Operator：object_add.cc:1053 的 OBJECT_OT_lightprobe_add（idname 在 :1058）——菜单一「添加 → Light Probe」就走它。
  • 引擎侧：draw/engines/eevee/eevee_lightprobe.hh:207 的 LightProbeModule，逐物体同步入口 sync_probe（:239），自动烘焙开关 auto_bake_enabled_（:228）。实现按类型分文件：eevee_lightprobe_sphere/planar/volume.cc。

动手实验：加一个体积探针

官方二进制控制台逐段执行（默认场景即可）：

import bpy
bpy.context.scene.render.engine = 'BLENDER_EEVEE'
# 预期：切到 EEVEE —— 探针是光栅引擎的概念
bpy.ops.object.lightprobe_add(type='VOLUME', location=(0, 0, 1))
probe = bpy.context.active_object
probe.type, probe.data.type
# 预期：('LIGHTPROBE', 'VOLUME') —— 探针是一种物体，数据块是 LightProbe
[(p.name, p.type) for p in bpy.data.lightprobes]
# 预期：[('LightProbe', 'VOLUME')] —— 场景里的探针数据块清单
probe.data.influence_distance
# 预期：一个浮点 —— 影响范围；探针参数都是 DNA，随文件存盘

看效果：3D 视口切到「渲染」着色模式（Z 菜单），在探针范围内放几个不同颜色的物体，能看到物体表面染上彼此的间接色。把引擎切回 'BLENDER_EEVEE' 之外的 Cycles 再渲——探针物体还在场景里，但 Cycles 完全不理它。
