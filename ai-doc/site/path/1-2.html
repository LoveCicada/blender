1.2 DNA 是磁盘布局

按 Ctrl+S 存下的 .blend 里到底有什么？答案是 DNA：一组 C 结构定义，只回答「这块内存怎么排」。它不管挤出怎么算，也不管像素怎么画。

路径索引 1.1 数据块 1.2 DNA 1.3 RNA

目标

  • 说出哪些字段进 .blend、哪些不进（runtime）。
  • 理解「打开文件 = 按布局说明书重建内存结构」，不是加载一棵场景树。

概念：布局说明书

source/blender/makesdna/ 下的 DNA_*_types.h 是一群 C 结构体定义：Mesh、Object、Scene、Material……存盘时，Blender 按这些定义把每个数据块原样写进文件；读盘时按同一份定义重建。

跨版本怎么办？构建期工具 makesdna 会把这些头文件编成一张结构表（SDNA），原样塞进每个 .blend 的 DNA1 块。旧版本打开新文件时，拿文件里的表和自己的表逐成员对齐——字段没变就整块拷，变了就按成员重建。所以十几年的旧文件还能打开。

关键分界线：不是所有字段都进文件。结构上挂着 runtime 指针（运行时缓存，比如编辑态 BMesh）明确不存盘。保存前必须能从它重建出纯 DNA 数据。

源码走读：Mesh 的布局

source/blender/makesdna/DNA_mesh_types.h:147 的 struct Mesh：

ID id;                 /* :154  上一课的 ID 头 */
AnimData *adt;         /* 动画数据，紧跟 id */
Material **mat;        /* 材质槽 */
int verts_num;         /* :168  顶点数 */
int edges_num, faces_num, corners_num;
/* ... CustomData 属性层、标志位 ... */
bke::MeshRuntime *runtime;   /* :345  不存盘 */

对照着看：verts_num 进文件；runtime 不进。下一课会看到，RNA 给这些字段起对外名字时，也是挑着来。

动手实验：存盘前后，与摸不到的 runtime

用默认启动场景（一个立方体），控制台执行：

import bpy
me = bpy.context.object.data    # 立方体的 Mesh
len(me.vertices)                # 预期：8
len(me.polygons)                # 预期：6

然后 Ctrl+S 存盘，Ctrl+N 重开再打开这个文件，再数一次：还是 8 和 6。顶点数、面数是 DNA 字段，进文件了。

me.runtime
# 预期：AttributeError —— bpy 里根本没有这个属性
[p.identifier for p in type(me).bl_rna.properties if "runtime" in p.identifier]
# 预期：[] —— RNA 属性表里没有它

这就是「不存盘」在 Python 侧的样子：连摸都摸不到。编辑模式里的半边网格就挂在 runtime 里——这也是为什么「保存文件」和「正在编辑的 BMesh」之间必须有一次格式转换（阶段 3 细讲）。
