3.3 编辑模式的进出

按 Tab 进编辑模式，本质是一次格式转换：数组 Mesh 转成活的 BMesh，挂在 Mesh.runtime 上。编辑期间你改的是 BMesh，退出 Tab 才写回 DNA。

路径索引 3.2 玩 BMesh 3.3 编辑模式 3.4 挤出与 BMO

目标

  • 说出 Tab 进出各做了什么转换、转换结果挂在哪。
  • 用实验证明：编辑模式里 DNA 计数不变——改的是 BMesh。
  • 阶段验收概念题：说出为什么编辑模式不直接改 DNA。

概念：为什么不直接改 DNA

既然 Mesh（DNA）里就有全部几何，编辑模式为什么不直接改它？三个理由：

  • 邻接查询：3.1 说过，编辑操作问的是邻接问题，数组答不动——所以要转成指针网再干活。
  • DNA 是存盘布局（1.2）：它只该在「进出编辑模式」和「存盘」这种边界时刻变。每次拖顶点都动文件格式，撤销、求值、渲染全要被拖进编辑细节里。
  • runtime 的定位：编辑态 BMesh 挂在 Mesh.runtime->edit_mesh——正是 1.2 说的「不存盘的运行时字段」。保存前能从 BMesh 重建出纯 DNA，所以 .blend 里永远没有编辑态。

源码走读：Tab 按下去之后

入口 editmode_enter_ex（editors/object/object_edit.cc:866）。网格分支的关键三行：

EDBM_mesh_make(ob, scene->toolsettings->selectmode, use_key_index); /* :898 造编辑态 BMesh */
BMEditMesh *em = BKE_editmesh_from_object(ob);                        /* :900 拿到它 */
...                                                                   /* 算法线等派生数据 */
WM_main_add_notifier(NC_SCENE | ND_MODE | NS_EDITMODE_MESH, nullptr); /* :905 通知：模式变了 */

EDBM_mesh_make（editors/mesh/editmesh_utils.cc:294）转到 EDBM_mesh_make_from_mesh（:300），转换核心是 BM_mesh_bm_from_me（bmesh/intern/bmesh_mesh_convert.cc:318）；退出时反向走 BM_mesh_bm_to_me（:1668）。注意 :905 又是 2.3 的通知通道——模式切换也是一条 notifier。

动手实验：编辑态里 DNA 不变

选中立方体，控制台逐段执行：

import bpy, bmesh
ob = bpy.context.object
bpy.ops.object.mode_set(mode='EDIT')

bm = bmesh.from_edit_mesh(ob.data)   # 拿到活的编辑态 BMesh
bm.verts.ensure_lookup_table()
bm.verts[0].co.x += 1.0
bmesh.update_edit_mesh(ob.data)      # 视口立即反映
# 预期：视口里立方体一个角移动了 —— 不用退出编辑模式
bm.verts.new((0, 0, 3))              # BMesh 里加一个顶点
len(bm.verts), len(ob.data.vertices)
# 预期：(9, 8) —— BMesh 9 个，DNA 还是 8 个
# 退出 Tab 后 DNA 才写回；这就是「编辑态 ≠ 文件数据」

收尾：bpy.ops.object.mode_set(mode='OBJECT') 退出编辑模式，再读 len(ob.data.vertices) → 9。写回发生在边界，正如预期。
