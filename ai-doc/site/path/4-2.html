阶段 4 · 求值与分身 · 第 2 课

4.2 两张图

同一个场景，视口和 F12 各建一张 depsgraph。建图时就定死一个模式：视口要快，渲染要全——修改器级别、物体可见性都按模式分叉。

路径索引 4.1 求值副本 4.2 两张图

目标

  • 说出 eEvaluationMode 两个值及各自的使用者。
  • 演示细分修改器「视口级别 1、渲染级别 2」在视口图里只算级别 1。
  • 阶段验收：解释修改器为什么在求值时跑，而不是点按钮时跑。

概念：一个场景，两种「算完的样子」

视口要流畅：细分级别低一点、被视口隐藏的物体别算。渲染要完整：细分级别拉满、只按渲染隐藏开关过滤。两种需求不可能用同一份求值结果满足，所以 depsgraph 在建图那一刻就带上模式：

  • DAG_EVAL_VIEWPORT：视口图。你在 3D 视图里看到的一切都从它来。
  • DAG_EVAL_RENDER：渲染图。按 F12 时渲染管线自己建一张，算完即弃。

分叉点写在数据里：细分修改器有 levels（视口）和 render_levels（渲染）两个字段；物体有 hide_viewport 和 hide_render 两个开关。建图和求值时按模式各取所需——这就是为什么「视口看着挺光滑，F12 更光滑」。

源码走读：模式在哪定、在哪分叉

  • 模式枚举：depsgraph/DEG_depsgraph.hh:46 的 enum eEvaluationMode：DAG_EVAL_VIEWPORT = 0（:47）、DAG_EVAL_RENDER = 1（:48）。
  • 建图带模式：DEG_graph_new（depsgraph/intern/depsgraph.cc:279）。F12 的渲染图在 render/intern/pipeline.cc:1977 以 DAG_EVAL_RENDER 建成。
  • 按模式分叉的例子：建图选可见性标志时，视口图查 COLLECTION_HIDE_VIEWPORT（depsgraph/intern/builder/deg_builder_relations_view_layer.cc:41）。
  • 两个级别字段：DNA_modifier_types.h:265 的 short levels = 1, renderLevels = 2——默认值本身就不同。

动手实验：视口图只认 levels

选中立方体，控制台逐段执行：

import bpy
ob = bpy.context.object
mod = ob.modifiers.new("S", 'SUBSURF')
mod.levels = 1          # 视口级别
mod.render_levels = 3   # 渲染级别（F12 用）

dg = bpy.context.evaluated_depsgraph_get()
len(ob.evaluated_get(dg).data.vertices)
# 预期：级别 1 的数量 —— 控制台的图是视口图，render_levels 不参与
mod.levels = 2
bpy.context.view_layer.update()
dg = bpy.context.evaluated_depsgraph_get()
len(ob.evaluated_get(dg).data.vertices)
# 预期：数量涨一档 —— 视口图只跟着 levels 走

render_levels = 3 的那一份，控制台里摸不到：它只在按 F12 时，由渲染管线自建的那张 DAG_EVAL_RENDER 图算出来（pipeline.cc:1977），算完即弃。想亲眼确认，可以按一次 F12 对比渲染图与视口的平滑度。
