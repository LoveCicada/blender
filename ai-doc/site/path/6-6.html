6.6 约束：求值时算变换的规则

约束和修改器是平行的两套「叠加效果」：修改器改几何，约束改变换。加了 Copy Location 的物体，location 一个字节都不会变——约束结果写在求值后的矩阵上，这正是阶段 4「原始数据不动」思想在变换层的回响。

路径索引 6.1 几何节点 6.2 合成 6.3 雕刻 6.4 UV 6.5 权重 6.6 约束 6.7 EEVEE 探针 6.8 变换 6.9 曲线 6.10 形态键

目标

  • 说出约束与修改器的分工：一个改变换，一个改几何。
  • 在 depsgraph 求值链上指出约束的位置。
  • 用 bpy 加 Copy Location 约束，验证 location 不变而 matrix_world 变。

概念：规则叠在变换上

约束回答的问题是「这个物体的位置/旋转/缩放，由别的什么决定」：跟着另一个物体走、朝向相机、沿路径运动、限制范围。要点：

  • 存的是规则，不是结果：约束列表是 DNA（随文件存盘），每条是一个 bConstraint，串成链表按顺序执行。
  • 结果在求值时算：depsgraph 求值物体变换时跑约束栈，输出最终矩阵。DNA 里的 location 保持用户输入的原值。
  • 骨骼有独立的一套：姿态骨骼（pose bone）有自己的约束栈，绑定、IK 都靠它——和物体约束同思想、不同入口。
  • 所以「物体明明跟着别人跑，属性面板里的位置却没变」不是 bug：面板显示的是 DNA，运动发生在求值层。

源码走读：链表与求值点

  • 约束的 DNA：DNA_constraint_types.h:668 的 bConstraint（:669 的 next/prev——链表）；类型枚举 :98–107，比如 CONSTRAINT_TYPE_LOCLIKE（:107）就是 Copy Location。
  • RNA 入口：rna_object.cc:3407 的 constraints 集合（bpy 里 ob.constraints.new(...) 就走它）。
  • 求值点：object_update.cc:94 的 BKE_object_eval_constraints，在物体 uber 求值里被调用（:397）——和修改器同一场求值，不同环节。
  • 骨骼侧：armature_update.cc:901 的 BKE_pose_constraints_evaluate——姿态骨骼的约束栈入口。

动手实验：location 不变，世界矩阵变

官方二进制控制台逐段执行（默认立方体 + 一个 Empty）：

import bpy
ob = bpy.context.active_object
tgt = bpy.data.objects.get("Empty")
if tgt is None:
    bpy.ops.object.empty_add(location=(3, 0, 0))
    tgt = bpy.context.active_object
    bpy.context.view_layer.objects.active = ob
# 预期：场景里有立方体 ob 和位于 (3,0,0) 的 Empty
con = ob.constraints.new('COPY_LOCATION')
con.target = tgt
tuple(round(v, 2) for v in ob.location)
# 预期：(0.0, 0.0, 0.0) —— DNA 里的位置没动
dg = bpy.context.evaluated_depsgraph_get()
dg.update()
tuple(round(v, 2) for v in ob.matrix_world.translation)
# 预期：(3.0, 0.0, 0.0) —— 求值后的世界矩阵已经跟上 Empty
tgt.location = (0, 5, 0)
dg.update()
tuple(round(v, 2) for v in ob.matrix_world.translation), tuple(ob.location)
# 预期：((0.0, 5.0, 0.0), (0, 0, 0)) —— 目标动，矩阵跟；DNA 位置始终不变

收尾：ob.constraints.remove(con)，再 dg.update()，立方体回到 (0,0,0)——约束没了，求值结果回到 DNA 原值，全程没「改」过物体。
