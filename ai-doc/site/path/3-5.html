3.5 修改器

修改器是挂在物体上的变形流水线：你存盘的只有参数（DNA），真正的变形发生在求值时，打在原始网格的副本上。

路径索引 3.4 挤出与 BMO 3.5 修改器

目标

  • 说出「参数进 DNA、变形在求值」各落在哪个文件。
  • 用 evaluated_get 演示：原始网格和求值副本的顶点数不同。

概念：存参数，算副本

加一个细分（Subsurf）修改器，网格没有立刻变密——因为修改器只做两件事：

  • 参数存进 DNA：级别、类型等字段在 SubsurfModifierData 里，随 .blend 存盘。这就是为什么重开文件修改器还在。
  • 变形留给求值：depsgraph 求值时（2.3 标脏的下游），把原始网格复制一份，在副本上跑修改器的 modify_mesh。原始网格从头到尾不动。

这个设计一次解释三个日常现象：加修改器那一刻网格不变密；视口级别和渲染级别可以不同（求值时按场景各算各的）；Apply 按钮才是「把求值结果写回 DNA」的显式操作。

源码走读：Subsurf 的两半

类型登记在 modifiers/intern/MOD_subsurf.cc:446 的 modifierType_Subsurf：

/*struct_name*/ "SubsurfModifierData"   /* :449 参数结构，是 DNA，随文件存盘 */
/*type*/ ModifierTypeType::Constructive   /* :452 构造类：会增删几何 */
/*modify_mesh*/ modify_mesh               /* :464 变形入口：求值时被调 */

求值侧：blenkernel/intern/mesh_data_update.cc:280 的 mesh_calc_modifiers——depsgraph 求值一个网格物体时，在这里依次跑修改器栈（调用点如 :947）。「改参数 → 标脏 → 求值重跑」就是 2.2 + 2.3 的链再走一遍。

动手实验：原始 8 顶点，副本暴涨

选中立方体，控制台逐段执行：

import bpy
ob = bpy.context.object
mod = ob.modifiers.new("S", 'SUBSURF')
mod.levels = 2
len(ob.data.vertices)
# 预期：8 —— 原始网格没动（参数进 DNA，变形在求值）
dg = bpy.context.evaluated_depsgraph_get()
ev = ob.evaluated_get(dg)
len(ev.data.vertices)
# 预期：远大于 8 —— 细分结果只存在于求值副本
mod.show_viewport = False
bpy.context.view_layer.update()      # 让标脏结算一次
dg = bpy.context.evaluated_depsgraph_get()
len(ob.evaluated_get(dg).data.vertices)
# 预期：回到 8 —— 视口级别关掉，副本就是原样

三段连起来就是本课标题的全部含义：参数（DNA）→ 求值（depsgraph）→ 副本（渲染/视口用）。
