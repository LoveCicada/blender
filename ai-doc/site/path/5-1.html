5.1 视口一帧

视口每画一帧，进 Draw Manager 时假定 depsgraph 已经求过值（4.1）。画什么由着色模式决定：线框 / Solid 走 Workbench，材质预览走 EEVEE，Rendered 走当前渲染引擎。overlay（线框罩、选中描边）不是引擎，是最后叠上去的一层。

路径索引 4.2 两张图 5.1 视口一帧 5.2 EEVEE

目标

  • 说出视口一帧的入口和「图已求过」的假定。
  • 说出四种着色模式各自由谁画；解释 overlay 为什么不是渲染引擎。

概念：画之前，算已经结束了

2.3 说通知让区域重画，4.1 说空档里 depsgraph 求值。到真正画这一帧时，顺序是：先求值（拿副本），再进 Draw Manager。所以绘制代码拿到的全是求值副本，自己不触发任何重算——视口卡顿时，先怀疑求值，再怀疑绘制。

画什么取决于着色模式（Z 键菜单）：

  • 线框 / Solid：Workbench 引擎——快，不编译材质节点。
  • Material 预览：EEVEE 引擎——即使你的渲染引擎选了 Cycles（下课细讲这个分叉）。
  • Rendered：当前场景渲染引擎（EEVEE / Cycles / 第三方）。

引擎列表在 source/blender/draw/engines/：eevee、workbench、overlay、select、gpencil……注意 overlay 也在其中，但它是绘制引擎，不是渲染引擎：你不能按 F12 让 overlay 出图。它只在视口最后叠一层辅助显示（网格线、选中描边、游标）。

源码走读：DRW_draw_view

入口 DRW_draw_view（draw/intern/draw_context.cc:1767）：

Depsgraph *depsgraph = CTX_data_expect_evaluated_depsgraph(C);  /* :1769 假定已求值 */
...
RenderEngineType *engine_type = ED_view3d_engine_type(scene, draw_ctx.v3d->shading.type);
                                                              /* :1779 按着色模式选引擎 */
drw_draw_render_loop_3d(draw_ctx, engine_type);               /* :1784 主绘制循环 */

选引擎的逻辑在 ED_view3d_engine_type（editors/space_view3d/view3d_draw.cc:1626）：默认用场景的渲染引擎，但材质预览（OB_MATERIAL）且引擎声明了 RE_USE_EEVEE_VIEWPORT 时，换成 EEVEE（:1634-1635）——这就是「材质预览常走 EEVEE」的落点。

动手实验：着色模式与引擎表

控制台逐段执行：

import bpy
bpy.types.View3DShading.bl_rna.properties["type"].enum_items.keys()
# 预期：['WIREFRAME', 'SOLID', 'MATERIAL', 'RENDERED'] —— 四种模式
bpy.context.scene.render.bl_rna.properties["engine"].enum_items.keys()
# 预期：['BLENDER_EEVEE', 'BLENDER_WORKBENCH', 'CYCLES'] 一类
# —— F12 可选的渲染引擎表；注意里面没有 overlay
bpy.context.scene.render.engine
# 预期：'BLENDER_EEVEE'（5.x 默认）

界面印证：在 3D 视图按 Z 切换四种着色模式，对照上面的引擎表体会「谁画哪一档」；再按 F12，体会 Rendered 预览和真渲染用的是同一个引擎。
