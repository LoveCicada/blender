5.2 EEVEE 与 GPU 材质

材质预览几乎总是 EEVEE 在画——哪怕你的渲染引擎选了 Cycles。材质节点树在 EEVEE 里被编译成 GPU 材质（GLSL），同一份节点语义，另一套机器码。

路径索引 5.1 视口一帧 5.2 EEVEE 5.3 F12 链

目标

  • 说出材质预览为什么常走 EEVEE（哪个标志、哪行代码）。
  • 说出节点树 → GPU 材质的编译入口。
  • 用 bpy 建材质、加 Principled 节点，在材质预览里看到它。

概念：一套节点，两套后端

你在着色器编辑器里搭的节点树是语义：「基础色乘纹理，进 Principled 的 Base Color」。谁来执行这份语义？

  • EEVEE（视口 / F12 都可以）：把节点树编译成 GPU shader（GLSL compute / fragment），在显卡上跑。编译入口是 GPU 层的 GPU_material_from_nodetree。
  • Cycles（5.4）：把同一棵树翻译成自己的 shader 闭包，在 CPU/GPU 上路径追踪。两套机器码，一份节点语义。

材质预览模式（Z → Material）需要一个能实时编译节点树的引擎——这正是 EEVEE 的本职。所以即使场景渲染引擎是 Cycles，材质预览默认仍由 EEVEE 代画（引擎声明 RE_USE_EEVEE_VIEWPORT 时）。

源码走读：EEVEE 的注册与材质编译

  • EEVEE 引擎注册：draw/engines/eevee/eevee_engine.cc:86，idname 是 "BLENDER_EEVEE"（5.x 里 EEVEE Next 已扶正为这个 id）。
  • 材质预览分叉：view3d_draw.cc:1634——OB_MATERIAL 模式且引擎带 RE_USE_EEVEE_VIEWPORT，就换成 RE_engine_id_BLENDER_EEVEE（:1635）。
  • 节点 → GPU 材质：gpu/intern/gpu_material.cc:134 的 GPU_material_from_nodetree；EEVEE 侧调用点在 eevee_shader.cc:1574。

动手实验：bpy 建材质

选中立方体，控制台逐段执行：

import bpy
mat = bpy.data.materials.new("M")
mat.use_nodes = True
nt = mat.node_tree
bsdf = nt.nodes["Principled BSDF"]     # use_nodes 自动带的主节点
bsdf.inputs["Base Color"].default_value = (0.8, 0.2, 0.1, 1.0)
bpy.context.object.data.materials.append(mat)
# 预期：3D 视图切到 Material 预览（Z 菜单）后，立方体变成橙红色
[n.name for n in nt.nodes]
# 预期：['Principled BSDF', 'Material Output'] —— 默认两节点
[(l.from_node.name, l.to_node.name) for l in nt.links]
# 预期：[('Principled BSDF', 'Material Output')] —— 一条链接

你看到的颜色 = 节点树经 GPU_material_from_nodetree 编译成 GPU 材质后由 EEVEE 画出。改 default_value 再观察：颜色即时变——节点改动触发标脏，GPU 材质缓存失效重编译。
