1.4 Main 与 Scene

Main 是进程里全部数据块的数据库；Scene 只是其中一块。一个文件可以有多个 Scene，但只有一份 Main。bpy.data 就是 Main 的 Python 视图。

路径索引 1.3 RNA 1.4 Main 与 Scene

目标

  • 说出 Main 与 Scene 的关系：数据库 vs 其中一块数据。
  • 分清「文件里有」与「当前场景里有」：物体属于 Main，场景只是组织方式。

概念：数据库与一幕戏

前三节课的数据块都存在哪？答案是 Main：进程内按类型串起来的 ID 集合。你在控制台敲的 bpy.data.objects、bpy.data.meshes，列的都是 Main 里的内容——不管它属于哪个场景。

Scene 是 Main 里的一块普通数据块，装的是「一幕戏」的设置：帧范围、渲染引擎、分辨率、指向当前 View Layer 的指针。物体并不「住在」某个 Scene 里；它们住在 Main 里，被场景的集合（Collection）引用。所以同一个物体可以出现在多个场景，也可以哪个场景都不出现（还留在文件里）。

源码走读

source/blender/blenkernel/BKE_main.hh:241 的 struct Main：按类型分的 ID 列表、文件路径、库链接关系都在这。Operator 里的 CTX_data_main(C) 拿的就是它。

source/blender/makesdna/DNA_scene_types.h:2863 的 struct Scene：开头同样是 ID id;——Scene 自己也是数据块，遵守 1.1 课的全套规则。

动手实验：两个场景，一份数据库

import bpy
len(bpy.data.scenes)        # 预期：1
bpy.context.scene.name      # 预期：'Scene'
len(bpy.data.objects)       # 记下这个数，比如 1（默认立方体）
s2 = bpy.data.scenes.new("Second")
len(bpy.data.scenes)        # 预期：2
bpy.context.window.scene = s2
bpy.context.scene.name      # 预期：'Second' —— 界面顶部场景名也变了
len(bpy.data.objects)       # 预期：和刚才一样，物体还在 Main 里
bpy.context.scene.collection.objects   # 新场景的集合是空的
bpy.context.window.scene = bpy.data.scenes["Scene"]   # 切回去

体会：新建场景没有复制任何物体；bpy.data 从头到尾没变。变的是「正在看哪一幕」。
