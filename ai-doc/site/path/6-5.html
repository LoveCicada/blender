6.5 权重与顶点组：数值在网格，名字在物体

6.4 说 UV 是面角域的数据；权重是它的对照组——顶点域的数据：每个顶点带一串「（组编号，0–1 权重）」。最反直觉的设计是：数值存在 Mesh 上，组的名单却存在 Object 上——共享网格的两个物体，可以有各自的顶点组名单。

路径索引 6.1 几何节点 6.2 合成 6.3 雕刻 6.4 UV 6.5 权重 6.6 约束 6.7 EEVEE 探针 6.8 变换 6.9 曲线 6.10 形态键

目标

  • 说出权重是顶点域数据，和 UV 的面角域对照。
  • 解释「数值在 Mesh、名单在 Object」的分离设计及其后果。
  • 用 bpy 建顶点组、赋权重、读回来。

概念：一份稀疏的每顶点数值

顶点组（vertex group）解决「给一部分顶点各配一个强度」的问题：蒙皮时这根骨骼影响哪些顶点、影响多深；物理时哪些点固定。设计上它是稀疏的：

  • 每个顶点带一个 MDeformVert：里面是一串 MDeformWeight（组编号 + 权重）。没进任何组的顶点，这串是空的——不花内存。
  • 组编号是整数下标，不是名字。名字列表（「脊柱」「左手」）存在 Object 的 vertex_groups 里，编号即名单里的位置。
  • 后果：两个物体共享一份 Mesh 时，权重数值共享、组名单各自独立——同名不同序就会张冠李戴，这是共享网格的经典坑。
  • 消费方按「名字 → 编号 → 权重」查表：骨骼修改器就是最大的消费方。权重绘制（Weight Paint）则是 6.3 那套笔画框架的又一个实例。

源码走读：两处存储与消费

  • 数值的 DNA：DNA_meshdata_types.h:162 的 MDeformWeight、:172 的 MDeformVert（:179 的 dw 指向权重串）。
  • 挂在 Mesh 上：DNA_mesh_types.h:316 的 dvert 字段，访问器 deform_verts()（:424）；自定义数据类型编号 CD_MDEFORMVERT（DNA_customdata_types.h:32）。
  • 名单的 RNA：rna_object.cc:3428 的 vertex_groups——注意它定义在 Object 的 RNA 里，不在 Mesh。
  • 消费方示例：MOD_armature.cc:115 的 deform_verts——骨骼修改器按组名找编号、按编号取权重，逐顶点变形。

动手实验：建组、赋值、读回

官方二进制控制台逐段执行（默认立方体，物体模式）：

import bpy
ob = bpy.context.active_object
me = ob.data
vg = ob.vertex_groups.new(name="Top")
vg.index
# 预期：0 —— 名单在物体上，编号是它在大名单里的位置
me.vertices[0].groups
# 预期：空 —— 还没赋值；稀疏设计：没进组的顶点不存任何权重
vg.add([0, 1, 2], 1.0, 'REPLACE')
[(g.group, g.weight) for g in me.vertices[0].groups]
# 预期：[(0, 1.0)] —— 数值落在 Mesh 的顶点上，存的是编号不是名字
vg.add([0], 0.25, 'REPLACE')
me.vertices[0].groups[0].weight
# 预期：0.25 —— 权重就是 0–1 的浮点，含义由消费方解释

想直观验证「名单在物体」：复制这个物体（Shift+D 联动复制），给副本的顶点组改名——两个物体的 vertex_groups 名单各自独立，但 me.vertices[*].groups 里的数值是同一份。
