render / Cycles

F12 按引擎字符串分发

RENDER_OT_render（editors/render/render_internal.cc）→ RE_RenderFrame → RE_engine_render → RE_engines_find(scene.r.engine)。未知 id 回落到 BLENDER_EEVEE。

渲染入口 Depsgraph Draw / 视口 EEVEE / Workbench F12 / Cycles

它解决什么

F12 要按场景里的引擎字符串分发，再另建 DAG_EVAL_RENDER 图。Cycles 把求值物体同步成自己的 scene / kernel，不读编辑态 BMesh，也不复用 EEVEE 的 GPU 材质机器码。

Cycles 怎么接到场景

Python CyclesRender（intern/cycles/blender/addon/__init__.py，bl_idname = 'CYCLES'）→ _cycles.render。BlenderSync::sync_data（intern/cycles/blender/sync.cpp）从 depsgraph 迭代求值物体；网格 object_to_mesh（util.h）。

节点 → 闭包

intern/cycles/blender/shader.cpp：sync_materials → add_nodes / add_node，目标 SHD_OUTPUT_CYCLES，再 SVMCompiler。运行时 kernel/svm/closure.h。与 EEVEE 的 GPU_material_from_nodetree 分道。

和建模收束

Cycles 看到的是求值网格（修改器已按 Render 模式应用）。编辑模式的 BMesh 不会直接进 kernel。改拓扑必须写回并标脏——B + C 已经把这条说完。

和邻居的边界

层它写什么它不写什么
RENDER_OT_render按 scene.r.engine 分发自己不算光
BlenderSync求值物体 → Cycles scene不读 edit_mesh
kernelSVM / 闭包 / PathTrace不跑 BMesh 算子

设计选择

未知引擎 id 回落 BLENDER_EEVEE。Cycles 经 Python bl_idname = 'CYCLES' 注册进同一张表。

常见误解

视口 Material 预览常走 EEVEE（RE_USE_EEVEE_VIEWPORT）。Rendered + Cycles 才是 external engine。
