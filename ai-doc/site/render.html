求值之后如何分道

视口和 F12 共享求值结果，不共享像素后端。函数级走读：渲染。

目录 模块 职责 功能 UI–数据 渲染地图

求值后的场景 → Draw / EEVEE 或 Cycles

视口

View3D 指定着色类型。draw 拉起 Workbench 或 EEVEE，经 gpu 出帧。选中高亮、线框是 overlay 引擎，不是 Cycles。

F12

editors/render 叫 render。引擎若是 Cycles，走 intern/cycles 的 sync → BVH → integrator → kernel。结果进图像缓冲，不是 DrawManager 的 framebuffer。

材质为什么两边都能用

用户编辑的是同一份 shader node tree。EEVEE 把它编成 GPU shader；Cycles 编成自己的闭包/SVM。兼容是「语义尽量对齐」，不是同一份机器码。

和建模的关系

渲染器看到的网格通常是 求值后 的：修改器已应用、实例已展开。编辑模式的 BMesh 不会直接丢进 kernel。所以改拓扑要先写回 Mesh 并标脏。
